# Project Context

## Project Summary

- Name: Project Guardian.
- Purpose: Provide a lightweight project memory plugin for teams that use AI-assisted coding and need durable handover context inside the repository.
- Target users: Small project teams, interns, project owners, and AI coding assistants that need a stable record of project purpose, current state, decisions, changes, and handover guidance.
- Business owner: Internal AI engineering or the team that maintains this repository.

## Tech Stack

- Runtime: Node.js 18 or newer.
- Framework: No application framework. The CLI uses only Node.js standard library modules.
- Database: None.
- Package manager: npm is optional for target projects, but this repository now exposes a package CLI through `guardian` and `project-guardian`.
- Deployment target: Global CLI install, local repository plugin folder, AI tool adapter rules, Codex plugin marketplace metadata, Git hooks, and Gitee Go workflow templates.

## Core Business Flows

1. Initialize project memory.
   - Entry point: `guardian init` when the package is installed globally, or `node plugins/project-guardian/scripts/guardian.js init` when the plugin source is vendored into the project.
   - Important files: `plugins/project-guardian/scripts/guardian.js`, `plugins/project-guardian/assets/templates/*`.
   - Rules: Create standard memory files without overwriting existing project-written memory.
   - Known edge cases: Existing projects may already have partial memory files, so the CLI must preserve them and report what was skipped.

2. Install AI tool adapters.
   - Entry point: `guardian install-adapters --adapter cursor,copilot` or `guardian init --adapter all`.
   - Important files: `plugins/project-guardian/scripts/lib/adapters.js`, `AGENTS.md`, `.cursorrules`, `.cursor/rules/project-guardian.mdc`, `.github/copilot-instructions.md`, `.github/instructions/project-guardian.instructions.md`.
   - Rules: Adapter files tell Codex, Cursor, Copilot, and generic AI agents to read and update Project Guardian memory; existing adapter files are preserved.
   - Known edge cases: Teams can configure default adapters in `project-guardian.config.json`, while one-off commands can override them with `--adapter`.

3. Enforce memory quality before commits.
   - Entry point: `guardian check`, `guardian validate-docs`, and `guardian verify`.
   - Important files: `plugins/project-guardian/scripts/guardian.js`, `project-guardian.config.json`, `.guardianignore`.
   - Rules: Code changes should include meaningful memory updates, memory files should not remain empty templates, and likely secrets should not be written into memory.
   - Known edge cases: Pure formatting or metadata changes may not need memory updates; teams can tune ignore patterns and quality options through config.

4. Preserve handover and decision context.
   - Entry point: `guardian update`, `guardian handover`, and `guardian decision add`.
   - Important files: `STATE.md`, `DECISIONS.md`, `docs/AI_CHANGELOG.md`, `docs/HANDOVER.md`.
   - Rules: Each AI-assisted change should explain what changed, why it changed, how it was verified, what risk remains, and what the next developer should know.
   - Known edge cases: Fresh `init` output is intentionally incomplete and should fail validation until the team fills real project context.

5. Resolve project memory conflicts.
   - Entry point: `guardian conflicts`.
   - Important files: Git conflict state, root memory files, and `docs/decisions/*.md`.
   - Rules: Preserve useful historical entries from both sides, keep state dates accurate, and rerun `guardian verify` after resolving conflicts.
   - Known edge cases: Merge conflicts only appear after Git records unresolved paths, so a normal working tree reports no conflicts.

6. Query local project knowledge.
   - Entry point: `guardian query` and `guardian query "question"`.
   - Important files: memory files, source files, markdown files, YAML files, and recent Git history.
   - Rules: Query is local keyword retrieval, not a hosted AI service. It should show source paths so a developer can verify the answer.
   - Known edge cases: Semantic search, vector indexes, and issue tracker retrieval are planned later and are not required for the current version.

## Data Model

| Entity | Important fields | Notes |
| --- | --- | --- |
| Project memory | Context, state, decisions, changelog, handover | Stored as Markdown files so humans and AI assistants can read them directly |
| Guardian config | Memory paths, quality rules, hook behavior, CI defaults, security scan switch, adapter defaults, ignore patterns | Stored in `project-guardian.config.json` with zero-config defaults |
| Decision record | Title, date, context, decision, alternatives, affected files, verification, risks, review date, follow-up | Stored in `DECISIONS.md` and optionally mirrored as a per-decision file |
| Decision file | One Markdown file per important decision | Stored under `docs/decisions/` when `guardian decision add` is used |
| Query document | File path, chunk text, score | Built at runtime from memory files, source files, markdown/yaml files, and Git history |

## How To Run

```bash
# syntax check
node --check plugins/project-guardian/scripts/guardian.js

# initialize memory in a target project
guardian init

# install adapter rules for other AI tools
guardian install-adapters --adapter cursor,copilot

# run the full local quality gate
guardian verify

# run tests
npm.cmd test
```

## Important Constraints

- The CLI must remain lightweight and usable in small repositories without service setup, databases, or paid APIs.
- The default workflow must work on Windows PowerShell and common Unix shells.
- Existing project memory must be preserved; generated templates and update commands should append or amend instead of deleting human context.
- Security checks must report file and line numbers while redacting suspicious values.
- Documentation should stay practical for non-expert developers and avoid relying on unspoken AI chat history.

## AI Notes
